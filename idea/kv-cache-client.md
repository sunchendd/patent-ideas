# 客户端持有 KV Cache 的 LLM 推理

> 原始想法（一句话级别的点子）。完整过程材料见 `workspace/kv-cache-client/`。

## 痛点
现在所有大模型推理的 KV Cache 都由**服务端独占管理**：老化快（秒~分钟级被淘汰）、客户端看不见也控不了、跨会话/跨天没法复用、用户上下文表征长期留在服务方（数据主权/合规问题）、每次请求都要重新上传全量 prompt 重算 Prefill。

## 核心点子
把 KV Cache 的**持久化主体搬到客户端**：服务端 Prefill 完把上下文 KV 编码成"可携带表示（PKB）"返回客户端，客户端存起来、自己管生命周期；后续请求时客户端用降维索引在本地挑出 top-k 块，只稀疏+差分地上传，服务端校验解码后直接进 Decode（预测不准就 miss-and-fill 补传）。

## 为什么现在能做
DeepSeek V4 类模型把 1M token 的 KV Cache 压到原来的 7%~10%，首次进入"可跨广域网络传输"的量级——这是本想法成立的新技术前提。
